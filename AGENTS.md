# Agent instructions

These apply to every coding agent working on Better-TG-CLI (Claude Code, Codex, Cursor and
others).

## Read first

1. `CLAUDE.md`: the project's rules (branches and pull requests, PR titles and versions, the
   `teleproto` MTProto library, build, release). They apply to every agent, not only Claude.
2. `DEVELOPMENT.md`: how to run the CLI from source (`scripts/tg-dev`), the mock account
   (`TG_MOCK=1`, nothing reaches Telegram) and the tests.
3. `docs/internals.md`: why the code is the way it is (workarounds, security reasons, protocol
   quirks, thresholds, platform specifics), grouped by module.

The short version: one task, one branch, one pull request into `next`; prefer mock data; never
write `dist/` from a watcher; the version lives only in `package.json`.

## Code style

- **No comments in code files** (`.ts`, `.mts`, `.mjs`, `.js`, `.cjs`, `.sh` and extensionless
  shell scripts). The only exceptions:
  - a shebang line (`#!`);
  - generated files (`src/version.ts`, `src/skill-files.ts`, `src/plugins/manifest-schemas.ts`,
    `src/generated/**`), whose generators write a single "Generated by …" header line;
  - a JSDoc block (`/** … */`) directly above an exported declaration (`export function`,
    `const`, `class`, `interface`, `type`, `enum`, `export default`) or above a public member of
    an exported class.

  Tool directives that are comments (`// @ts-expect-error`, `/// <reference …>`,
  `// oxlint-disable …`) are not allowed either: remove the need for them. Put the "why" into a
  clear name, a JSDoc on the nearest export, or `docs/` (usually `docs/internals.md`). Plain
  "what" comments are not needed at all. In tests, the test name carries the intent.

- **Lint and format** with Ultracite on oxlint and oxfmt:
  - `npm run lint`: oxlint with the project's rules (`scripts/lint/no-comments.mjs`), the
    comment check for shell scripts (`scripts/lint/no-comments-sh.mjs`) and the format check;
  - `npm run fix`: safe autofixes, then the formatter;
  - `npm run format`: the formatter alone.

  Run `npm run fix` and `npm run lint` before a pull request; CI runs `npm run lint`. A rule the
  code base does not follow is turned off in `oxlint.config.ts` with its reason, never with an
  inline disable comment.

- **TypeScript:** prefer `unknown` to `any`, narrowing to type assertions, `as const` for literal
  data, and named constants to magic numbers.
- **Control flow:** early returns over nesting, braces around every `if` body, `async`/`await`
  over promise chains, and every promise awaited or deliberately handled.
- **Errors:** throw `Error` objects with a message a person can act on; do not catch an error
  just to rethrow it.
- **Tests:** assertions inside `it()`/`test()`, `async`/`await` instead of done callbacks, no
  `.only` or `.skip` in committed code, shallow `describe` nesting.
